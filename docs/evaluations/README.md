# 评测文档入口

先按问题选入口，不必读取全部历史报告。评测代码、专题分析方法、一次运行结论
和原始证据是不同层次；文件在仓库中不代表当前有效或已上线。

| 需要了解什么 | 入口 | 权威范围 |
| --- | --- | --- |
| 工程验证层级、何时运行检查 | [验证规范](../testing/verification-levels.md) | 当前项目测试政策；不授予真实资源执行权限 |
| 评测代码如何分层、新专题如何接入 | [工具总入口](../../scripts/eval/README.md) | 通用证据、Provider适配和专题的依赖边界 |
| 如何运行上下文评测、读取已有封存 | [上下文工具](../../scripts/eval/context/README.md) | Yui上下文场景、统计与证据契约，不决定业务收益或采用 |
| 上下文优化有哪些方向、如何分析线上轨迹 | [上下文评测专题](context/README.md) | 持续维护的方法与现状索引；版本和部署状态须复核 |
| 已授权历史Codex rollout成本统计 | [历史成本工具](../../scripts/context-cost/README.md) | 限定根会话、续接与时间窗的只读统计，不生成实验seal或质量结论 |
| 某次上下文候选、实验或历史交付结论 | [上下文报告目录](context/reports/README.md) | 仅对应报告中的时间、版本、来源和样本 |
| 代码审查质量评测 | [审查评测说明](../testing/review-evaluation.md) | 独立专题与工具，不套用上下文成本或Skill义务映射 |

## 文件布局与后续扩展

```text
scripts/eval/
  core/                         不含专题/Provider假设的字节与证据工具
  adapters/<provider>/          Provider协议和原生统计口径
  context/                      上下文评测执行、统计、场景及证据格式
  review/                       代码审查质量评测工具
docs/testing/                    项目验证政策与现有专项工具规范
docs/evaluations/
  README.md                     跨专题导航和文档边界
  <topic>/README.md              该专题的目标、方法、当前结论索引
  <topic>/reports/README.md      报告目录，标注种类、版本和范围
  <topic>/reports/<date>-<name>.md
                                实验、线上观察、离线归因或采用复核报告
```

只有出现新专题时才新增 `scripts/eval/<topic>/` 和文档 `<topic>`；不要预建一套
空模板/调度框架。后续记忆评测可用 `memory/`，自研Agent评测可用 `agent/`，
各自定义输入、身份、记忆/任务效果和质量判断；不继承上下文场景的四阶段、
Operator/Leader或Skill遵循标准。共享工具不依赖专题，专题之间不互相引用场景。
现有审查工具已归入 `scripts/eval/review/`，双语说明仍由 `docs/testing/` 维护，
从这里导航，不重复复制。新的上下文报告
继续放 `context/reports/`，不要散落 `docs/` 根目录、框架README或追加到旧长日志。

报告开头注明：报告类型（受控实验／线上观察／离线分析／交付复核）、问题、
时间窗、产品/Skill/框架身份、来源及覆盖、样本选择与完成量、结论强度。
正文区分工程统计、Agent解释和采用建议；末尾给出缺口和下一问题。
线上观察不伪装成随机对照；原件不可用就明确历史报告证据等级。

当前专题指南可随新证据更新并链接报告，但不得把历史结论静默改成当前事实。
后续纠正新建补充分析，注明替代的判断；不覆盖旧统计、评分、seal或原始轨迹。
框架修正写接口说明和检查，不把一次实验发现提升为所有专题的固定判定。

原始轨迹、构建归档、敏感来源和生成的大型统计保留在各自受控证据位置，报告
记录准确身份/hash及访问限制；不要为目录整洁而移动封存成员、公开原文或改变权限。
旧提交中的路径仍按当时Git树解释，本次整理不重写历史提交或封存内引用。
